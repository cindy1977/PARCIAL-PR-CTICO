# Guía rápida para el docente

## Antes del examen

1. Crear un repositorio en GitHub.
2. Subir el contenido de esta carpeta.
3. Mantener `main` como rama protegida si se desea evaluar el Pull Request.
4. Compartir con los estudiantes la URL del repositorio.

## Recomendación

Si cada estudiante trabaja con una cuenta propia, puede utilizar:

**Opción A — Colaboradores:** agregar a los estudiantes como colaboradores y pedirles que creen una rama individual.

**Opción B — Fork:** cada estudiante realiza un fork, crea su rama y abre el Pull Request según las reglas establecidas por el docente.

## Qué revisar en GitHub

### 1. Branches
Verificar que exista una rama como:

`feature/nombre-apellido`

### 2. Commits
Abrir el historial y verificar el commit del estudiante.

### 3. Pull Request
Comprobar:

- autor;
- rama origen;
- `main` como destino;
- archivos modificados;
- descripción;
- estado;
- merge.

### 4. Main
Después del merge, comprobar que el cambio del estudiante está integrado.

## Consejo para una evaluación objetiva

No otorgar todos los puntos solamente por el resultado final. La finalidad del examen es comprobar el dominio del flujo:

`branch → edit → add → commit → push → Pull Request → merge → pull`
